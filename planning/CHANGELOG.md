# Changelog

All notable changes to the PERL platform's plan and codebase are documented here, in [Keep a Changelog](https://keepachangelog.com/) format. This file exists so an AI coding agent (or a new human contributor) can understand what happened and why without reading every prior diff or PRD revision.

**Format for every entry going forward:**
- Group changes under `### Added`, `### Changed`, `### Fixed`, `### Removed`, `### Deferred`
- One bullet per logical change, in plain language, referencing the phase and file(s) touched
- Never delete or rewrite past entries — if something is superseded, say so explicitly in the new entry
- Keep unreleased work under `## [Unreleased]` until an actual deploy/release, then move it under a dated heading

### Security
- Security audit and hardening pass across `perl-api`, `docker-compose.yml`, `Dockerfile`, and `perl-rfid-device` (Phase 7 work, verified against four parallel attack-surface audits). Findings and fixes below, grouped by severity.
- **[CRITICAL] Fail-open secret defaults.** `validateRuntimeEnvironment` in `perl-api/src/config/env.ts` previously early-returned unless `NODE_ENV === 'production'` exactly, so any deploy with `NODE_ENV` unset, mistyped, or set to `staging` booted with the in-source default `JWT_SECRET` (`dev-phase-2-secret`), default DB password, and default `SYSTEM_ADMIN`/`SUPPORT` bootstrap passwords — all readable in source control, allowing an attacker to forge a valid `SYSTEM_ADMIN` session cookie and take over every tenant. The guard is now fail-closed: validation runs in every environment except an explicit `development` or `test` `NODE_ENV`, so staging/prod/unset all abort startup on any default or too-short secret.
- **[HIGH] Login user-enumeration via timing.** `AuthService.login` (`perl-api/src/services/AuthService.ts`) only ran `bcrypt.compare` when an account existed, so unknown emails returned far faster and were distinguishable. Login now always performs a bcrypt comparison against a fixed precomputed dummy hash on the not-found path, making timing constant regardless of whether the email exists.
- **[HIGH] No session revocation on logout.** Logout only cleared the cookie, leaving a captured JWT valid for its full 8h lifetime. Added an in-memory `jti` denylist in `perl-api/src/auth/session.ts` (random `jti` claim added at sign time, checked at verify time, expired entries pruned); `authController.logout` now revokes the presented token before clearing the cookie. Comment notes a shared store (Redis) is the multi-instance upgrade path.
- **[HIGH] Unaudited cross-school access by platform roles.** `SUPPORT`/`SYSTEM_ADMIN` could read and stream any school's attendance and admin data with no audit trail, and the `SUPPORT`-only browser scan simulation wrote real, unaudited attendance rows (contradicting the read-only + audited support model in CLAUDE.md §5/Phase 9). Added audit records: `SUPPORT_SCAN_SIMULATED` on simulated scans, `ATTENDANCE_LOGS_VIEWED`/`ATTENDANCE_STREAM_OPENED` on platform-role attendance reads (`perl-api/src/controllers/attendanceController.ts`), and `SCHOOL_DATA_VIEWED` on platform-role cross-school admin GETs (`perl-api/src/controllers/adminController.ts`). New action constants in `perl-api/src/types/Audit.ts`.
- **[HIGH] Unbounded attendance read (DoS).** A `STUDENT` filtering `GET /api/attendance/logs` forced `listAllBySchool` to load the school's entire attendance history into memory before filtering. Added a hard 5000-row cap (most-recent-first) in both `DbAttendanceRepository` and `MockAttendanceRepository`; `AttendanceService.getFilteredLogs` now requires a `from`/`to` date range once the cap is hit, surfaced as a 400. Normal paginated reads (DB-side `LIMIT/OFFSET`) unchanged.
- **[MEDIUM] JWT algorithm not pinned.** `perl-api/src/auth/session.ts` now pins `algorithm: 'HS256'` on sign and `algorithms: ['HS256']` on verify, closing a latent algorithm-confusion surface.
- **[MEDIUM] Missing security headers.** Added `helmet` (`app.use(helmet())`) and a catch-all Express error handler that returns a generic message with no stack trace regardless of `NODE_ENV` (`perl-api/src/app.ts`, `perl-api/package.json`).
- **[MEDIUM] Rate-limiting gaps.** `perl-api/src/middleware/rateLimitMiddleware.ts` now evicts stale entries (was unbounded, attacker-controlled login keys could grow memory) and exposes an IP-only login key so credential-stuffing across many emails from one IP is throttled; added a per-user rate limiter on `PATCH /auth/profile` password changes (`perl-api/src/routes/authRoutes.ts`).
- **[MEDIUM] Container/infra hardening.** `Dockerfile` now runs as the unprivileged `node` user instead of root; `docker-compose.yml` no longer publishes the Postgres port to the host (DB reachable only on the internal compose network).
- **[LOW] CSV formula injection.** `perl-api/src/utils/csv.ts` guard extended to escape leading tab (`\t`) and carriage return (`\r`) in addition to `= + - @`, since user-controlled name fields flow into admin-opened CSV exports.
- **[LOW] Misc hardening.** `cardUid` on the scan endpoint is now type-checked (was truthiness-only, accepted objects); bcrypt cost raised from 10 to 12 at all hashing call sites (`AuthService`, `AdminService`, mock seeds); firmware `isValidApiBaseUrl` (`perl-rfid-device/perl_rfid.ino`) now accepts `https://` so a TLS deployment can be configured (a `WiFiClientSecure` client remains a follow-up).
- **Known follow-ups (not fixed this pass — design/hardware tradeoffs):** kiosk device key persisted in browser `localStorage` (`perl-rfid-frontend/src/pages/DeviceKioskPage.tsx`) is XSS-readable; firmware still sends over plaintext HTTP without a TLS client; `SchoolDataService` backup export includes raw bcrypt/device-key hashes; no CSRF token (currently mitigated by `SameSite=Lax` cookies + strict CORS allow-list).

- Pulled tenant/school UI branding (`SchoolProfile`: name, logo, theme colors) forward to **Phase 1**, ahead of auth and persistence, since visibly-different-per-school UI is the core SaaS differentiator and is cheap to validate against mock data. See `AGENTS.md` Section 4.
- Simplified the role model: dropped the `SUPER_ADMIN` / `platform_users` split introduced in v2.0 Sprint 0 until an actual multi-tenant support workflow exists. Four roles only (`ADMIN`, `STAFF`, `STUDENT`, `GUARDIAN`), scoped by `schoolId`. See `AGENTS.md` Section 5.
- Testing philosophy clarified: mock only the data-access boundary and true external services (payment provider, SMTP, S3); business logic (attendance admit/deny rules, role scoping, theming resolution) is tested against real implementations, not stubbed. See `AGENTS.md` Section 7.

### Deferred
(Previously scheduled early in v2.0; explicitly pushed later — see `AGENTS.md` Section 8 for full rationale)
- Stripe billing service (`perl-billing`) — was v2.0 Sprint 4, now post-Phase 8, gated on having an actual paying school.
- Redis pub/sub for the WebSocket layer — was mandatory from v2.0 Sprint 0, now deferred until real multi-tenant concurrent load is observed; Phase 3 uses a single in-process event emitter instead.
- Platform admin console + audited `SUPER_ADMIN` impersonation — was v2.0 Sprint 5, now deferred until there's a real support workload.
- Database-per-tenant / schema isolation option, custom domains beyond subdomain, multi-region infrastructure — all deferred until a concrete customer or compliance requirement demands them.

### Unchanged from v2.0 (carried forward as-is)
- The requirement for a Data Privacy Impact Assessment (DPIA) and Data Processing Agreement (DPA) under RA 10173 (Philippine Data Privacy Act) before public launch with real students' data — now Phase 8 instead of Sprint 5, same substance.
- The non-negotiable security baseline (bcrypt not MD5, HttpOnly cookies not `localStorage`, no wildcard CORS, no credentials in URLs or source) — reframed in `AGENTS.md` Section 10 as day-one defaults for a fresh build, rather than a remediation backlog, since v3.0 assumes we are building new rather than patching v1.0's legacy codebase.

## [2.0.0] - 2026-07-22 — SaaS conversion from single-tenant PRD

### Added
- Multi-tenancy model: shared database with `tenant_id` row-level scoping on all tenant-owned tables.
- Subscription plans (Starter, Growth, Enterprise) and a `perl-billing` service (Stripe Checkout, Customer Portal, webhooks, usage metering).
- Tenant onboarding flow (self-serve signup, trial period) and a device-provisioning-code flow binding devices to one tenant.
- `perl-ws` rebuilt around Redis pub/sub with tenant-scoped channels, replacing the original global-broadcast design.
- Platform-level `SUPER_ADMIN` role, separated from tenant `users` table, with an audited support-access grant flow.
- Compliance section: RA 10173 (Philippine Data Privacy Act) requirements — DPO designation, DPIA, DPA template, breach notification runbook — given the platform processes minors' attendance data across many schools on shared infrastructure.
- New sprint tracks: Sprint 0 (multi-tenancy foundation), Sprint 4 (billing & onboarding), Sprint 5 (platform ops & compliance), layered on top of the original v1.0 Sprint 1–3 security/quality work.

### Changed
- Re-scoped the whole product from "one school, one VPS" to "many schools, shared infrastructure, subscription SaaS."
- Elevated several v1.0 findings (notably C-09/C-11 WebSocket auth gaps and H-04's hardcoded `deviceId: 1`) from "production bug" to "cross-tenant data leak risk," since the multi-tenant context makes them more severe, not less.
